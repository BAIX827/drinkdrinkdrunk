# 大喝特喝：互动调酒教程与我的吧台

状态：需求草案，供产品方向核对。本文记录已表达的想法与待确认的设计决定；当前阶段只规划功能。

## 一句话目标

让用户登记家里的调酒材料，找到当前材料可以制作或接近可以制作的配方，再通过卡通动画和可调节节奏的“跟做模式”，一边动手调酒，一边查看下一步。

## 核心使用流程

1. 用户进入“我的吧台”，把家里的酒、果汁、糖浆等材料登记到可视化架子上。
2. 用户选择要检查的材料类别，查看“所检查材料齐全”“最多缺 1 项”“最多缺 2 项”的配方，并看到具体缺少的材料。
3. 用户打开配方详情，查看配料、用量、杯型和做法，选择“开始跟做”。
4. 用户选择常见鸡尾酒杯，教程按配方步骤展示酒瓶、摇壶、杯子等器具的卡通动作，并同步显示文字和用量。
5. 教程按用户设置的节奏自动前进；用户可以暂停、继续、回看或跳到下一步。

## 需求 A：我的吧台与卡通库存

### A1. 材料登记

- 用户可以登记酒类和非酒类材料，包括果汁、糖浆及配方用到的其他常见材料。
- 每件材料由用户命名，并选择一个用于配方匹配的**标准材料类型**。用户给酒瓶起的名字用于展示，标准类型用于匹配。例如，名为“我的蓝瓶酒”的材料选择“金酒”类型后，可匹配需要金酒的配方。
- 类型需要支持适当的细分，例如白朗姆和黑朗姆、干味美思和甜味美思，避免仅凭宽泛类别产生错误推荐。
- 用户可以随时增加、编辑、移除材料。现有“我的酒”登记记录在升级时应保留。

### A2. 卡通外观与摆放

- 酒架提供几个具有辨识度的预设卡通酒瓶造型，例如威士忌、金酒、伏特加、朗姆等；其他材料提供适合其类型的容器造型。
- 用户可以选择造型、调整颜色，也可以自己画材料的卡通外观。
- 已登记材料以卡通图像摆放在架子上。酒类和果汁、糖浆等材料可以分区展示，整体保持现有 App 的色彩与界面风格。
- 用户为材料选定或绘制的外观，在跟做动画中优先复用，让教程画面与个人库存相连。

## 需求 B：按库存发现配方

- 用户可选择参与检查的材料类别，例如只检查酒类，或同时检查酒类、果汁和糖浆。
- 推荐结果按所选检查范围计算缺少的材料项数。建议提供三个筛选档位：缺 0 项、最多缺 1 项、最多缺 2 项；每张配方卡显示具体缺少什么。
- 当用户只检查部分材料类别时，结果明确写为“按所选材料检查”，避免把未检查的材料算作已经拥有。
- 材料匹配使用标准类型与细分类别，用户自定义名称和卡通颜色不影响计算。
- 用户更新库存后，推荐结果和配方详情中的缺料提示同步更新。

## 需求 C：配方详情与跟做模式

### C1. 配方步骤

- 配方需要拆成有顺序的操作步骤。每步至少包含：动作、材料与用量、使用器具、目标容器、屏幕提示，以及对应的动画。
- 动作覆盖常见调酒操作：量取与倒入、加冰、搅拌、shake（摇匀）、过滤、倒入最终酒杯、补满和装饰。
- 摇壶与最终盛酒的鸡尾酒杯分别呈现。例如“威士忌 10 ml”步骤可展示酒瓶打开、向摇壶倒入，并在画面上突出显示“10 ml”；后续再展示摇匀和倒入所选杯型。
- 用量以配方数据和文字提示为准；液体动画表达操作顺序和大致变化。

### C2. 画面与杯型

- 酒瓶、器具、液体与杯子采用统一的卡通画风，沿用当前 App 的配色、圆角和视觉语言。
- 用户可从几种常见鸡尾酒杯中选择最终杯型。支持用户自己画杯子作为后续扩展方向。
- 教程始终显示当前步骤、总步骤数、用量和下一步提示，方便用户在操作中快速看清。

### C3. 播放节奏与操作

- 默认以自动演示为主，支持设置步骤之间的等待时间，适应不同熟练度。
- 提供醒目的暂停、继续、上一步、下一步控制。触摸操作是可选互动方式，教程可仅靠自动播放完成。
- 为“边调边看、尽量解放双手”的场景预留语音播报、操作时保持屏幕常亮等能力；是否作为首版要求待确认。

## 两个功能如何相连

“我的吧台”影响配方推荐和缺料提示。进入跟做模式后，教程优先展示用户为已拥有材料设置的卡通容器外观。用户从“我有这些材料”自然进入“我能做什么”，再进入“现在怎么做”。

## 现有项目需要补充的数据

- `CocktailRecipe` 目前把配料保存为文字数组，把做法保存为一段文字。逐步动画需要可读取的结构化步骤与用量。
- `MyLiquorStore` 目前只保存酒类名称集合。可视化库存需要材料类型、用户名称、卡通外观及非酒类材料的数据。
- 当前缺料判断主要按酒类名称检查。推荐功能需要覆盖用户选择的材料类别，并处理细分类型和同义名称。
- 配方库现有 120 款。建议先用几款不同操作类型的配方验证步骤模型与动画，再逐批整理其余配方。

## 建议的实施顺序

1. 定义标准材料类型、库存记录和配方步骤结构，处理旧库存记录的迁移。
2. 完成库存匹配与筛选，让推荐结果可核对。
3. 完成“我的吧台”的预设卡通容器、换色、摆放与材料编辑。
4. 完成跟做模式的基础动作动画、杯型选择及播放控制。
5. 加入用户自绘酒瓶外观，并复用到酒架和教程；逐批覆盖 120 款配方。
6. 按需求确认结果安排自绘杯型、语音提示等扩展。

## 待确认的产品决定

1. “最多缺 1 / 2 项”目前按**上限**理解：最多缺 1 项的结果也包含材料齐全的配方。
2. 首版库存先记录“有 / 没有”。是否还需要记录每瓶剩余毫升数与用量扣减？
3. 自动播放采用统一的步骤间隔，还是允许每一步单独设置等待时间？摇匀等有实际操作时长的步骤可能需要单独计时。
4. 语音播报与屏幕常亮是否列入首版范围？
5. 用户自绘外观优先用于酒瓶整体轮廓、瓶身标签，还是两种方式都要支持？
