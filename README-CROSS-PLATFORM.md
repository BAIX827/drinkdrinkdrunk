# 大喝特喝：iOS、网页与 Mac 共用吧台

项目保留原 SwiftUI iOS 应用，在原有“我的酒”入口接入新吧台。新功能使用同一套本地 HTML、CSS、JavaScript，网页直接运行，iOS 和 Mac 通过系统 WKWebView 加载。没有前端运行时依赖、远程字体或必需的网络图片。

## 在 Windows 上运行

已安装 Node.js 22 或更高版本时，在项目目录运行：

```bat
cd /d C:\Users\64969\Desktop\drinkdrinkdrunk
npm.cmd start
```

打开 http://127.0.0.1:5173 。不需要 `npm install`。停止时在终端按 Ctrl+C。也可双击项目根目录的 `启动网页版.cmd`。

服务只监听当前电脑的回环地址，不向局域网或公网开放。修改前端文件后刷新页面即可。浏览器数据按地址隔离，请固定使用这个地址，避免混用 localhost 或不同端口。

## iOS

用 Xcode 打开 `Cocktail60.xcodeproj`，选择 `Cocktail60` scheme、开发团队和 iPhone / 模拟器后运行。

- 底部“我的吧台”打开共用界面。
- 原配方详情增加“开始跟做 · 查看我的材料”入口。
- 首次打开吧台时迁移 `myOwnedLiquors`，原名称保留为展示名称；不认识的名称留在“待选择类型”区域，不猜测材料。
- 吧台库存和收藏写回原有 store；收藏也会读取原生页面的最新改动。
- 原生自建配方可在新吧台中查看和跟做。新吧台新增的配方、文字日记保存在独立共用数据中，仍从新吧台访问。
- 新吧台使用本地存储，同时将状态备份到 `UserDefaults.sharedBarStateV1`，避免依赖 WebView 缓存位置。保存的内容可通过 JSON 备份迁移到网页或 Mac。

原有小红书导入、照片日历、系统小组件和原生外观设置继续留在原 iOS 界面。网页和 Mac 实现项目计划中的吧台与教程，以及收藏、自建配方和文字日记；尚未移植上述 iOS 专属功能。

## Mac 桌面应用

在 Mac 上安装 Apple 的 Xcode Command Line Tools，然后在项目目录运行：

```sh
bash scripts/build-mac.sh
```

脚本编译当前 Mac 架构的原生窗口、复制共用吧台资源、进行本机 ad-hoc 签名，并打开 `build/大喝特喝.app`。Mac 不需要 Node、Electron 或常驻网页服务器；已提交的 `BarWeb/data.js` 随 App 打包。数据保存在该应用的本地存储中。

此脚本用于本机开发。面向其他用户分发时，仍需 Apple 开发者签名及公证。Windows 无法编译或签名 Apple 应用，因此本次交付不含已验证的 `.app` / `.ipa` 安装包。Mac 声明最低版本 13.0，实际 WebKit 行为仍需 Mac 验收。

## 功能与边界

- 120 款配方文本、用量和杯型从原 Swift 数据导出。
- 94 个标准材料类型，支持别名、方向明确的父子类型，以及“黑麦或波本”等替代关系。
- 材料按酒类、果汁、糖浆与糖、饮料与乳品、水果与其他分类。缺 0 / 最多缺 1 / 最多缺 2 按上限计算。可选项不计入必需材料；方法里额外出现的装饰和未列出的冰块需另备，界面明确说明。
- 库存仅记录有无，不扣减毫升。展示名称、颜色、手绘内容不会改变匹配。
- 四类预设容器、颜色选择、手绘标签与瓶身涂鸦，外观复用于酒架和教程。自由修改整个瓶子轮廓、自绘酒杯属于后续扩展。
- 120 款内置配方均有结构化跟做步骤：12 款单独编排，其余通过有限的原方流程模板生成。新配方遇到无法识别的做法会在构建时失败，避免静默生成错误步骤。自建配方显示备料与完整原方指引。
- 量取、加冰、轻压、摇匀、搅拌、过滤、倒入、补满、装饰、搅打、漂浮和洗杯均有动作状态。动画表示操作与大致液体变化，文字用量为准。操作时长是演示节奏，不是对实际风味或稀释程度的保证。
- 自动播放、暂停/继续、上一步/下一步、5/8/15/30/60 秒等待、五种最终杯型；摇匀/搅拌取操作时长和等待设置的较大值。切到后台自动暂停，返回后手动继续。
- 跟做完成后可一键加入饮酒日记，直接保存当天日期、配方名称、当前杯型与酒液颜色，无需先填表。日记卡片显示当时的酒杯外观，之后可补充备注或编辑。同一次完成防止重复点击记账；重新调一杯可生成新记录。旧文字日记仍可读取。
- 饮酒日记采用月历：支持前后月份与回到今天；日期格展示当天酒杯，超过两杯显示余下数量；点击日期查看完整记录，补记默认使用选定日期。保存或修改日期后自动定位到对应月份，杯型和颜色继续复用保存时的外观。
- 教程冰块使用透明 SVG 方冰，依次落入器具、回弹后停留；倒酒和搅拌继续保留冰块，过滤入杯不带入摇壶冰块，搅打后不再展示整块方冰。五种成品杯复用统一杯身轮廓，冰块布局、液面裁切、酒流终点跟随所选杯型。暂停/继续保留动画进度，减少动态效果时展示静态结果。
- 语音依赖系统语音引擎；屏幕常亮依赖环境支持，失败时显示明确提示。减少动态效果遵循系统偏好。
- 浏览器 / iOS / Mac 数据各自本地保存，尚无账号或云同步。备份导入明确确认替换，格式错误不覆盖现有内容。

## 文件与验证

```text
Cocktail60/BarWeb/
  core.js          标准类型、匹配、迁移和备份校验
  app.js           页面、编辑表单和本地持久化
  player.js        跟做播放器与计时生命周期
  art.js           复用 SVG 容器与酒杯
  data.js          自动导出的配方与步骤，不手动修改
data/
  tutorials.json   12 款单独编排的教程
  procedures.mjs   原有做法到结构化步骤的有限模板
Cocktail60/BarWebHost.swift   两个 Apple 平台共用的本地 WebView 桥接
Cocktail60/BarWebView.swift   iOS SwiftUI 入口
macOS/                      Mac 原生窗口与应用信息
scripts/                    导出、构建和本地服务
tests/                      材料匹配、数据一致性、迁移及步骤顺序测试
```

```bat
npm.cmd run verify
```

构建会更新 `Cocktail60/BarWeb/data.js`，并复制静态网站到 `dist/`。修改 Swift 配方、教程或步骤模板后应重新构建。`dist/`、`build/` 不提交 Git；iOS/Mac 打包需要的共用源文件及生成的 `data.js` 保留在仓库。

Windows 自动检查不能代替 Apple 平台验收。发布前需在 Xcode 验证编译、旧数据迁移、关闭再打开后的保存、原生收藏互通，以及在 Mac 验证构建与菜单操作。
